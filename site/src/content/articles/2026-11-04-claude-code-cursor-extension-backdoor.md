## 元記事の要旨

- セキュリティ企業のPhorionは、Cursor Marketplaceで配信されていた「Claude Code for VS Code」拡張機能のバージョン2.1.312および2.1.313に、SSHバックドアが組み込まれていたことを報告しました。Cursorは対象の版を削除済みです。
- バックドアは拡張機能の起動処理前に実行されるスクリプトを含み、ユーザーのSSH許可鍵リストに攻撃者の公開鍵を追加した上、外部サーバーへの逆向きSSHトンネルを開設して長期的かつ対話的なアクセス権を獲得しようと試みます。
- macOS向けの処理にはバグが存在し、管理者権限なしでSSH状態を確認しようとして失敗するため、SSHの自動有効化処理が実行されない問題が指摘されています。ただし、すでにSSHが有効な環境ではバックドアとして機能する状態になります。
- 拡張機能はエディタおよび実行ユーザーと同じ権限で動作するため、読み込まれた時点でローカルファイルやソースコードへ直接アクセスされます。該当バージョンを利用していた組織には直ちに影響範囲の調査と対応が推奨されています。

## 議論の論調

### 事故の影響範囲と攻撃対象となった配布経路の確認

Anthropicの関係者は、本件が自社の開発システムや公式のVS Codeマーケットプレイスの侵害ではなく、Cursor側のマーケットプレイス経由で配布された非公式な改ざんパッケージによるものだと説明しました。公式版の利用者には影響がないと主張されていますが、コミュニティからは第三者ストアでの公式ブランド表示や検証体制の甘さを懸念する声が上がっています。

### 拡張機能マーケットプレイスにおける検証と電子署名の欠落

VS Code拡張機能の配布基盤やサードパーティ製ストアにおいて、コード署名や厳格な発行者検証が存在しない設計リスクが指摘されています。公式の表示名やブランドが容易に偽装・複製可能である現状において、開発者が安全に拡張機能を入手・利用するための技術的な仕組みが不足している点が議論されています。

### AI開発ツールをローカル環境で動かす際のセキュリティ対策

エージェント型のAI開発ツールはローカルファイルやコマンド実行に対して広大な権限を持つため、今回のようなサプライチェーン攻撃を受けた際の被害が甚大になると警戒されています。対策として、ホスト環境から孤立させた仮想マシンやコンテナ内部だけでツールを実行し、秘密鍵や本番データへのアクセスを制限する運用が推奨されています。

## 用語

- **SSH（Secure Shell、暗号化リモートシェル接続プロトコル）**: ネットワーク経由で他のコンピュータに安全にログインし、リモート操作を行うための暗号化通信プロトコルです。
- **IIFE（Immediately Invoked Function Expression、即時実行関数式）**: JavaScriptにおいて、関数が定義された直後に自動的に呼び出されて実行される構文パターンです。
- **RCE（Remote Code Execution、遠隔コード実行）**: 攻撃者が外部から対象システム上で任意のプログラムやコマンドを実行できてしまう脆弱性や攻撃手法です。
