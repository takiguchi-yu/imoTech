## 元記事の要旨

- Claude Codeの「再表示しない」設定により、承認されたコマンド内のパスワードや鍵情報がローカル設定ファイルへ直接書き込まれる仕様が確認されました。
- 調査の結果、公開されているGitHubリポジトリのうち1,122件のファイルで該当の設定ファイルが誤ってコミットされ、機密情報が露出していることが判明しました。
- 露出したリポジトリの半数以上では、開発者だけでなくClaude自身が作成したコミットによって設定ファイルがリポジトリに追加・更新されていたケースが含まれていました。
- 開発元は、設定ファイルをリポジトリ管理外に配置することや、手動承認ではなく自動モードの利用、リポジトリ側での機密情報スキャンツールの活用を推奨しています。

## 議論の論調

### 漏洩の原因がユーザーの操作ミスかツールの仕様か

設定ファイルをGitの管理下に誤ってコミットした開発者側の不注意を指摘する声がある一方、ツール自身が設定ファイルをコミットに巻き込む挙動や、環境変数ではなく機密情報を含むコマンドをそのままファイルへ書き込む仕様を問題視する意見が出されています。

### 自動モード（Auto mode）利用に対する懸念

開発元は手動承認の繰り返しによる注意力の低下を防ぐため自動モードの推奨を挙げていますが、十分な隔離環境がない状態での自動実行はシステム破壊等のリスクを伴うため、安全策として不十分であるとの批判が多く集まっています。
