# M14: 記事一覧にもアイキャッチを出す

**Status:** 完了（本番に反映済み。レビューと検証の結果は末尾）
**Blocked by:** なし（M11 のアイキャッチがあること）

## なぜやるか

M11 でアイキャッチ（タイトルカードの PNG）を作り、記事ページと og:image に使った。
その時点の合意は「一覧には出さない」だったが、ユーザーが一覧にも出すよう指示した。

## 決めたこと（ユーザーの判断）

| 項目 | 決定 |
|---|---|
| 置き方 | **左に小さなサムネイル**、右にタイトルと日付。スマホでは画像をタイトルの上に |
| 対象 | トップの一覧と**タグ別一覧の両方** |

## 設計

- **概念**: `ArticleEntry.astro`（一覧の 1 項目）
- **責務**: 1 項目の見た目は部品が持ち、ページは並べるだけ。トップとタグ別で見た目が食い違わない
- **依存の向き**: pages → `ArticleEntry` → `lib/og`（画像のパスと寸法）/ `lib/sources` / `lib/articles`
- **画像のリンク**: `aria-hidden="true" tabindex="-1"` で読み上げとキーボードから外し、タイトルのリンクだけを残す。
  `alt=""` の画像だけのリンクは読み上げでリンク名が無くなる。画像とタイトルを 1 つのリンクで包む形
  （WAI が推奨する H2）も作れるが、画像・タイトル・日付を別々のグリッド領域に置く今の構造を組み直すことに
  なるので採らなかった（`docs/DESIGN.md` 2.6）

## 申し送り

- **一覧の画像は 1200×630 をそのまま縮めて使っている**（1 枚 45〜60 KB）。2 件目以降は遅延読み込みなので
  いまは問題ないが、公開記事が 20 本を超えたら、一覧用の縮小版（例: 440×231）を作ると転送量が減る
- **画像の文字と隣のタイトルが同じ**なので、一覧では同じ文字列が 2 回並ぶ。ユーザーが選んだ形
- **check-unpublished はタイトルだけの漏れを見ない。** 探すのは slug（リンクと画像のパスに入る）だけで、
  未公開記事のタイトルがリンクなしで HTML に出ても通る。また slug をファイル名から作るので、frontmatter に
  `slug:` を書くと（Astro の glob loader はそれを URL に使う）当たらなくなる。いま `slug:` を持つ記事は 0 件。
  RSS と sitemap の検査も同じ前提なので、直すならまとめて直す
- **検査スクリプトそのもののテストが無い。** 今回の穴は dist を手で壊して見つけた。固定のテスト用 dist で
  壊し方を回すテストがあれば、次に検査を変えるときに同じ穴を自動で拾える
- **tags を読めないときの失敗は、壊して確かめていない。** 本番の記事を書き換えないと再現できないため

### レビュー 1 周目（正確性 A・リスク C）

| 視点 | 深刻度 | 指摘 | 対応 |
|---|---|---|---|
| C | Major | 部品の class が変わって一覧の項目が 1 件も当たらないと、check-og がすべて空振りして成功で終わる | 項目の数を公開記事の数と突き合わせるようにした |

| A | Minor | 長い英単語で右の列がはみ出す | `minmax(0, 1fr)` と `overflow-wrap: anywhere` |
| A | Minor | 不採用案の理由（`display: contents`）が実際の判断と違う | WAI H2 を挙げて書き直した（本チケットと DESIGN） |
| A | Minor | 画像の大きさが「約 45 KB」だが実測は 45〜60 KB | 直した |
| A | Minor | DESIGN の一覧の節が 2.6 の途中に割り込んでいる | 2.6 の末尾に移した |

### レビュー 2 周目（リスク C のみ、差分レビュー）

| 深刻度 | 指摘 | 対応 |
|---|---|---|
| Major | タグ別のページを dist のディレクトリから数えているので、ページがまるごと（または 1 タグ分）無くても成功で終わる | 公開記事のタグから「あるべきページ」を作り、無ければ失敗、余分にあっても失敗にした |
| Minor | slug を部分一致で探すので、公開記事 `X-part2` へのリンクを未公開 `X` の漏れと誤判定する（正しい状態でデプロイが止まる） | 前後の区切りまで見るようにした |
| Minor | tags を JSON として読めないと expected が 0 になり、原因の分からない失敗になる | 読めないこと自体を名指しして失敗させるようにした |
| Minor | `\bentry\b` が `entry-foo` にも当たる | 空白区切りの 1 語として探すようにした |
| Minor | タイトルだけの漏れ・frontmatter の `slug:` に効かない | 申し送りに回した（RSS・sitemap の検査と同じ前提なので、まとめて直す） |

`entry-foo` の li を足す → 数えない / `X-part2` へのリンク → 誤検出しない / `X` のリンクと画像 → 検出する。すべて元に戻した。
